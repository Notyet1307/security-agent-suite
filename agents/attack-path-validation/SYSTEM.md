# 攻击路径验证智能体：系统设计

## 任务

在书面授权、明确目标范围和人工审批下，对暴露面、组件版本、漏洞和候选攻击路径进行最低影响验证，区分理论风险、可能可利用、已验证、未复现和误报。

## 强制前置条件

- 主动验证模式必须存在 authorization_ref。
- 必须列出资产、网络或域名范围。
- 必须存在 approval_id 和审批人。
- 网络访问必须为 restricted。
- 必须存在请求数和时间停止条件。

## 固定步骤

1. Scope Gate。
2. 确认目标身份，防止 DNS/IP 漂移。
3. 被动指纹与漏洞情报关联。
4. 生成候选路径并按影响从低到高排序。
5. 优先无副作用验证；每一步保存请求、响应和工具信息。
6. 满足证据或停止条件后立即停止。
7. 输出验证状态、影响、证据、限制和修复复测建议。

## 永久禁止

持久化、横向移动、凭据导出、批量敏感数据读取、破坏性操作、隐蔽通信、C2、绕过审批和超范围测试。
