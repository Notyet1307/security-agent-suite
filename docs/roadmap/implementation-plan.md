# Security Agent Suite 实施路线图

## 1. 目标定义

项目不是一次性完成“五个万能 Agent”，而是连续交付三个可验收层级：

| 里程碑 | 结果 | 预计总投入（已有内部工具前提） |
| --- | --- | ---: |
| v0.1 工程基线 | 五个独立入口、状态机、审批、Mock、Agent Pack、契约和 CI | 当前骨架已完成主体，约 8～12 人天等价工作 |
| v0.5 可演示 | 五个 Agent 都能在真实 agent-compose Sandbox 中运行，其中报告/合规具备真实闭环，其余连接最小真实工具 | 累计 40～60 人天 |
| v1.0 可试点 | 五个 Agent 均有真实数据源、证据链、固定评测集和客户场景验收 | 累计 95～145 人天 |
| v1.x 可商业交付 | HA、RBAC、审计、对象存储、升级、离线包、运维和安全测试 | 累计 140～205 人天 |

> 投入范围取决于现有流量分析、扫描器、SOC、知识库和报告工具是否已有可调用 API。若需要从零开发工具本身，不能按上述人天估算。

## 2. 全局依赖关系

```text
M0 工程基线（当前）
 └─▶ M1 真实运行时与环境核验
      └─▶ M2 证据与能力底座
           ├─▶ M3 报告智能体
           ├─▶ M4 合规智能体
           ├─▶ M5 事件研判智能体
           │    └─▶ M6 流量分析智能体
           └────────▶ M7 攻击路径验证智能体
                         │
                         ▼
                    M8 跨 Agent 闭环与评测
                         │
                         ▼
                    M9 生产加固与交付
```

M3～M5 可以部分并行；M7 不应早于授权、证据和隔离底座完成。

## M0：工程基线与公开仓库

### 目标

让五个智能体先成为可调用、可测试、可演进的独立产品接口，而不是五段 Prompt。

### 当前骨架已包含

- Go API、CLI、状态机、队列、幂等、租户、审批、取消、超时和恢复；
- Mock 与 agent-compose CLI Executor；
- 五个 Agent Pack、15 个 Skill、输出 Schema 和样例；
- agent-compose 声明、capset 边界和安全提示；
- 文件状态、Artifact、审计、指标；
- OpenAPI、CI、安全工作流、部署起步文件；
- 路线图和 GitHub Issue 清单。

### 你需要完成

1. 在 GitHub 建立公开仓库并推送当前基线；
2. 开启 main 分支保护：PR、CI、CodeQL、至少一人审查；
3. 确认 Apache-2.0、NOTICE 和参考项目边界；
4. 将当前版本标记为 `v0.1.0-alpha.1`；
5. 只接受通过 `make verify` 和 `make smoke` 的变更。

### 验收

- 新环境克隆后无需外部服务即可 `make verify && make smoke`；
- API 返回五个 Agent；
- 普通任务可完成，主动验证任务必须等待审批；
- 重复 `request_id` 不重复执行；
- 租户间不可查询彼此 Run。

### 建议投入

2～3 人天用于仓库设置、复核和首个 Release；主体代码已在本骨架中完成。

## M1：环境核验与真实 agent-compose 联调

### 目标

证明五个 Agent 都能在目标交付环境中由 agent-compose 启动、取消、超时并返回结构化结果。

仓库可达的 harness、Mock 和 CI 证据与真实 live 验收分开记录；Issue #9 仅关闭前者范围。SAS-108 是 live gate，不得用离线成功替代。

### 关键变量

- Linux 架构、Docker/BoxLite、磁盘、内存、网络和 DNS；
- agent-compose daemon/CLI 版本；
- Provider、模型、上下文限制和凭据；
- Sandbox 到 capability proxy 的可达性；
- Guest 镜像、时区、证书、代理和私有镜像仓库；
- 任务取消与服务重启后的真实状态。

### 任务

1. 新增 `sasctl doctor`：检查 Go 服务、agent-compose、Docker、镜像、daemon、OctoBus 和模型 Provider；
2. 固定 agent-compose 版本、Guest 镜像 digest 和 compose schema；
3. 对 Agent 最终输出执行 JSON Schema 强校验，明确受支持的 schema 子集和拒绝路径；
4. 将 CLI JSON、daemon run ID、sandbox ID、实际模型和 runtime 版本写入 Run；
5. 将 API cancel 传播到 agent-compose 真实 Run，并轮询到终态；
6. 建立 Provider 失败、Sandbox 失败、工具失败和输出失败的错误分类；
7. 在五个 Agent 上分别完成最小真实运行，并保存脱敏 evidence；
8. 对每个 Agent 完成一次真实 cancel 和 timeout，证明正确终态与 downstream acknowledgement；
9. 仅在有权威“未产生外部副作用”或幂等信号后增加瞬时错误重试；无信号时保持不重试；
10. 获取既有治理流程认可的 20 条外部 controls 独立 signed/independent attestation 及 validator、runtime build provenance；
11. 为目标 Mac mini/服务器建立环境基线文档和可重复检查脚本。

### 产物

- `doctor` 报告；
- 真实 executor 集成测试；
- 运行 provenance 字段；
- 五个 Agent 的 sandbox smoke evidence；
- 环境兼容矩阵；
- 20 条 controls attestation 及 validator、runtime build provenance 记录。

### 验收门槛

- 五个 Agent 各运行 20 次，100/100 次通过完整 evidence gate；
- 每个 Agent 一次真实 cancel 和一次 timeout，10/10 进入正确终态并有 downstream acknowledgement；
- 恰好 20 条独立外部 controls（四类 × 五个 Agent）由既有治理流程认可的 attestation 覆盖；
- 每次运行都有权威实际 model、Skill/tool 和 runtime-version provenance；
- 非 Schema 输出不能标记 succeeded；
- daemon、agent-compose 或 OctoBus 不可用时错误可识别，不产生假结果；
- Agent 无权使用未声明 capset，且瞬时错误没有无权威信号的盲重试。

### 建议投入

8～12 人天。

## M2：统一证据与 OctoBus 能力底座

### 目标

让后续五个智能体共享同一套可追溯事实，而不是各自产生互不兼容的文本。

### 任务

1. 建立上传/登记 Artifact API，支持大文件分片或预签名上传；
2. 实现 Evidence Store：append-only、哈希、来源、工具版本和参数；
3. 实现 Finding、Timeline、AttackPath 持久化和引用校验；
4. 建立 `security-evidence` OctoBus 服务；
5. 建立 capset 目录、服务包模板、方法级策略和审计字段；
6. 建立租户数据分区、敏感级别和留存删除规则；
7. 实现工具输出大小限制、脱敏、截断和原始 Artifact 保存；
8. 建立 Fixture 规范与来源 Manifest；
9. 增加证据完整率、引用有效率和工具错误率指标。

### 产物

- Evidence/Artifact 服务；
- 首批 OctoBus service package；
- 可查询的证据链；
- 固定 Fixture 数据集；
- capset 权限评审表。

### 验收门槛

- 任一 High/Critical Finding 无 Evidence 时校验失败；
- Evidence 可定位到原始 Artifact、工具和参数；
- 跨租户引用被拒绝；
- 同一 Artifact 哈希去重但保留租户权限；
- 工具输出中的密钥/令牌不进入普通日志。

### 建议投入

10～15 人天。

## M3：网络安全报告智能体 v1

### 为什么优先

风险低、数据可离线构造、展示效果快，同时会倒逼所有上游使用结构化协议。

### 首版范围

- 输入：CSV/JSON、Run Result、Evidence/Finding；
- 模板：日报、周报、月报、事件专项；
- 输出：DOCX、PDF、report-data.json、source/evidence manifest；
- 统计：事件、告警、资产、风险、处置状态、同比/环比（有可比周期时）。

### 任务

1. 定义指标字典：名称、公式、分子、分母、去重键、时区和缺失值；
2. 实现 CSV/JSON 解析与字段映射；
3. 实现确定性统计服务，LLM 不参与计算；
4. 建立模板注册表、版本和适用报告类型；
5. 用独立渲染服务生成 DOCX/PDF；核心控制仍由 Go 完成；
6. 执行数字、引用、空占位、分页和敏感字段检查；
7. 建立 10 个固定报告 Fixture 和 Golden 文件；
8. 支持人工编辑区与机器事实区分离。

### 验收门槛

- 所有数字与源数据 100% 一致；
- 不存在未替换占位符；
- 每个管理摘要数字可追溯到 metric ID；
- 相同输入和模板版本生成相同结构化数据；
- Word 可编辑，PDF 与 Word 核心内容一致。

### 建议投入

8～12 人天。

## M4：网络安全合规查询智能体 v1

### 首版范围

优先选 2～3 个高频体系，不要一次性覆盖所有法规：

- 网络安全等级保护；
- 关键信息基础设施保护；
- 商用密码应用安全性评估；
- 可按实际客户行业增加一个专项标准。

### 任务

1. 建立文档、版本、生效/废止、发布机构、章节和条款元数据；
2. 建立法规原文摄取、切分、校验和增量更新流程；
3. 检索必须返回原文定位，不只返回向量相似段落；
4. 建立适用性变量：地区、行业、主体、系统、数据、安全等级和时间点；
5. 建立 Control 与客户证据映射；
6. 使用规则引擎处理确定性判断，LLM 负责解释；
7. 建立引用真实性、版本和上下文校验；
8. 构造不少于 100 个问答和 30 个差距分析评测用例；
9. 明确“法律要求、标准要求、推荐实践、内部要求”四类语义。

### 验收门槛

- 条款引用存在率 100%；
- 版本和生效时间准确率 ≥ 98%；
- 没有客户证据时不输出已合规/不合规断言；
- 回答明确区分原文、解释、推断和建议；
- 关键问答由合规专家盲审通过率 ≥ 90%。

### 建议投入

12～18 人天，不含法规原文授权采购。

## M5：事件研判智能体 v1

### 首版范围

先支持 3～5 类高频事件：

- 异常登录；
- 恶意外联；
- Web 入侵；
- 恶意软件/终端告警；
- 扫描与爆破。

### 任务

1. 建立统一 Alert/Event/Asset/Account/Process/Connection Schema；
2. 接入一个真实告警源、资产源、终端/日志源和情报源；
3. 实现去重、聚合、时间窗口和实体关联；
4. 实现资产重要性、维护窗口、白名单和历史基线；
5. 固化“支持证据 + 反证 + 替代解释”的假设检验；
6. 建立严重性确定性评分和解释；
7. 只生成响应建议或工单草稿，不自动处置；
8. 建立误报、真阳性、证据不足和边界样本集；
9. 对输入提示注入和恶意日志开展测试。

### 验收门槛

- 每个结论同时展示支持证据、反证和缺口；
- 真阳性/误报测试集达到客户约定基线；
- 关键事件召回率优先于自动关闭率；
- 无证据时必须输出 `insufficient_evidence`；
- 不调用任何封禁、隔离、删除和关闭告警方法。

### 建议投入

15～22 人天。

## M6：网络流量包分析智能体 v1

### 首版范围

- 离线 PCAP；
- Zeek 日志；
- Suricata EVE；
- DNS、代理和终端日志的有限关联；
- 不做实时阻断和在线抓包控制。

### 任务

1. 建立大文件上传、哈希、格式、截断和时间范围检查；
2. 将 Zeek、Suricata、tshark/等价工具包装成只读能力；
3. 规范化连接、DNS、HTTP、TLS、文件和告警数据；
4. 实现会话归并、NAT/负载均衡/采样限制说明；
5. 建立统一时间线、时钟偏差和实体图；
6. 建立 IOC 丰富化，但禁止把 IOC 单独作为攻击成功证据；
7. 映射 ATT&CK 技术并记录映射依据；
8. 建立正常流量、恶意外联、横向移动、加密流量和截断样本；
9. 评估文件大小、处理时间、内存和输出上限。

### 验收门槛

- PCAP 解析结果可由命令行工具复核；
- 不从未解密流量声称看到明文；
- 时间线事件均有 evidence_id；
- 对截断、丢包、时钟偏差和采样明确告警；
- 1 GB 基准样本在目标硬件上满足约定 SLA。

### 建议投入

18～28 人天。

## M7：攻击路径验证智能体 v1

### 首版范围

只做授权范围内的低影响验证：

- 暴露资产/组件指纹复核；
- 厂商公告、CVE、受影响版本和前置条件关联；
- 扫描器结果复核；
- 已批准模板的单步验证；
- 攻击路径候选图和最小修复切断点；
- 不做自动后渗透、持久化和横向移动。

### 任务

1. 建立授权对象、目标清单、时间窗口、方法和停止条件模型；
2. 审批记录签名/不可变存储；
3. 实现目标身份确认、DNS 漂移和范围匹配；
4. 建立安全模板注册表，禁止任意 Shell/PoC；
5. 在 OctoBus 工具侧二次校验授权；
6. 建立请求计数、错误计数、速率和副作用熔断；
7. 保存请求模板、响应摘要、截图、版本、时间和哈希；
8. 区分 verified、likely、not_reproduced、false_positive、blocked、insufficient；
9. 构建资产—服务—漏洞—身份—网络区攻击图；
10. 开展越权、SSRF、DNS rebinding、提示注入和 Sandbox 逃逸专项测试。

### 验收门槛

- 零超范围请求；
- 未审批主动调用为零；
- 任何主动方法同时通过 Go 和工具服务两层校验；
- 达到停止条件后不再发送请求；
- “未复现”不自动等同于误报；
- 所有 verified 结果可以由人工按证据复核。

### 建议投入

20～32 人天。

## M8：跨 Agent 闭环与系统评测

### 目标

保持五个 Agent 可独立调用，同时允许显式编排：

```text
事件告警
 → event-triage
 → traffic-analysis（需要补流量证据时）
 → attack-path-validation（批准后）
 → security-report
```

合规智能体可独立使用，也可消费技术证据生成控制差距。

### 任务

1. 建立 WorkflowDefinition，不允许 Agent 隐式自行调用高风险 Agent；
2. 支持 Run 输入引用其他 Run 的冻结结果；
3. 实现证据去重、版本和 lineage；
4. 建立重试、补证、重新研判和人工修订语义；
5. 建立离线评测框架、Golden 数据集和回归门；
6. 指标覆盖正确性、证据、工具成功率、延迟、成本和安全；
7. 建立模型/Skill/工具升级的 A/B 和回滚；
8. 建立客户试点反馈和错误分类闭环。

### 验收门槛

- 跨 Agent 引用不复制或篡改原始证据；
- Workflow 可暂停、审批、取消和恢复；
- 任一模型/Skill/工具升级必须通过固定评测门；
- 报告能够追溯到最初数据源和每一步 Run。

### 建议投入

12～18 人天。

## 3. 三人小组的推荐并行方式

| 角色 | 主线 | 次线 |
| --- | --- | --- |
| A：平台/Go | M1、M2、M8、M9 | API、存储、鉴权、评测框架 |
| B：安全能力 | M5、M6、M7 | OctoBus 工具、证据和安全测试 |
| C：知识/交付 | M3、M4 | 模板、法规知识库、Fixture、验收材料 |

默认每个任务及其共享文件只有一个写作者；读者和审阅者可以并行，但同一核心状态或文件必须先完成明确交接。每阶段只允许一个“承重主线”，其他并行任务必须有稳定接口。

## 4. 最快可落地的六周节奏

| 周 | 重点 | 可展示结果 |
| --- | --- | --- |
| 第1周 | M0 收口 + M1 环境/真实 Sandbox | 五个 Agent 均可真实启动和返回 Schema |
| 第2周 | M2 Evidence/Artifact + 报告指标 | 证据可追溯，报告 Agent 可生成 JSON 报告 |
| 第3周 | 报告 DOCX/PDF + 合规语料首批 | 日/周/月报样例，合规带引用问答 |
| 第4周 | 事件研判首批场景 | 三类告警自动聚合、假设和建议 |
| 第5周 | 流量离线分析 | PCAP → Zeek/Suricata → 时间线/发现 |
| 第6周 | 攻击验证安全最小闭环 | 扫描结果 → 审批 → 低影响验证 → 证据 |

六周结果是“可演示和内部试用”，不是完整商业生产版本。

## 5. 每个阶段统一完成定义

任务只有同时满足以下条件才算完成：

- 代码、契约、文档和部署配置齐全；
- 正常、失败、超时、取消、重启和越权路径有测试；
- 真实 Fixture 和期望结果进入版本库或受控数据仓；
- 关键结论可追溯到 Evidence；
- 安全边界经过不产出该实现的独立 Review，并有独立验收记录；
- `make verify`、`make smoke` 和阶段评测通过；离线或 Mock 结果不得满足 live 验收门槛；
- live execution 有授权引用、非生产范围、停止/清理/保留决定及脱敏证据；
- 有升级和回滚说明；
- 演示效果不依赖人工临时改库或改 Prompt。
