# ADR-0001：核心控制面使用 Go

- 状态：Accepted
- 日期：2026-09-03

## 背景

项目需要长期运行的 API、状态机、队列、审批、审计和多个安全系统适配器。模型运行由 agent-compose 承担，因此核心语言的任务不是“写 Agent”，而是提供稳定边界。

## 决策

使用 Go 实现业务控制面、CLI、领域协议和适配器。初始版本只使用标准库，降低依赖和供应链复杂度。

## 理由

- 并发、取消、超时和长运行服务模型清晰；
- 静态编译、单文件部署、跨平台交付方便；
- 类型系统适合固定状态机和安全契约；
- 资源占用和启动速度适合内网私有化；
- 对 gRPC、HTTP、OpenTelemetry、PostgreSQL 和对象存储支持成熟；
- 团队后续可以逐步把 OctoBus 服务也用 Go 实现。

## 代价

- DOCX/PDF、PCAP 和部分安全生态在 Python 中更丰富；
- 不应强迫所有工具都改写成 Go，工具可保持独立进程或服务；
- Go 控制面不能承载任意插件代码，扩展通过显式端口完成。

## 结果

Go 是控制和集成语言，不是唯一工具语言。Python/Rust/现有产品能力可通过 OctoBus 接入。
