# ADR-0002：先采用模块化单体

- 状态：Accepted
- 日期：2026-09-03

## 决策

M0-M6 采用一个 Go 服务：API、策略、应用服务、队列和适配器在同一进程内，但通过 package 与 interface 保持边界。

## 理由

五个智能体真正的复杂度在工具、数据和评测，而不是微服务数量。过早拆服务会增加部署、鉴权、分布式事务和调试成本。

## 拆分触发条件

只有满足以下之一才拆分：

- 一个模块需要独立扩缩容；
- 安全边界要求独立网络区；
- 发布节奏和故障域明显不同；
- 数据所有权已经稳定；
- 单进程资源或可靠性成为已测量瓶颈。

优先拆分候选：Artifact 服务、Run Worker、报告渲染、主动验证审批与执行。
