# SAS-104 — Agent 输出 JSON Schema 强校验

## 状态

Proposed. Depends on SAS-102.

## Goal

Prevent an Agent run from reaching `succeeded` when its output violates the Agent's checked-in output contract, while preserving the original output for audit and diagnosis.

## Scope

- Validate the five checked-in Agent output contracts at the execution-result boundary.
- Enforce the supported schema subset: required fields, JSON types, object/array structure, enumerated values, and evidence-reference shape already defined by repository contracts.
- Return a structured validation error and retain the unmodified raw output.
- Apply the same rule to Mock and agent-compose execution results.

Complete JSON Schema Draft 2020-12 compatibility is out of scope for this issue.

## Required behavior

1. Valid output follows the applicable Agent contract and may complete normally.
2. Invalid JSON or contract-invalid JSON produces a failed Run; it cannot produce `succeeded`.
3. The original output remains available through the existing result/artifact/audit path.
4. Validation errors are structured JSON and identify the Agent, failed constraint, and safe location/path when available.
5. Missing or unknown Agent schema fails closed rather than accepting unvalidated output.
6. Validation is deterministic and does not ask the model to repair or reinterpret output.

## Security boundaries

- Treat Agent output as untrusted data.
- Do not infer evidence, metrics, citations, authorization, or scope from invalid output.
- Do not add arbitrary shell execution or network access to perform validation.
- Reuse existing contracts and dependencies; adding a third-party validator requires an ADR.

## Acceptance criteria

- [ ] Every five Agent output path is validated at the shared result boundary.
- [ ] A malformed JSON fixture fails and does not transition to `succeeded`.
- [ ] A structurally invalid fixture fails and reports a structured validation error.
- [ ] A valid fixture succeeds unchanged.
- [ ] Raw invalid output is retained and is byte-for-byte recoverable through the existing retention path.
- [ ] Missing schema coverage fails closed.
- [ ] Mock and agent-compose paths have contract tests.
- [ ] `make verify` passes.

## Implementation notes

Use the existing domain/app result transition and validation seams. Keep schema definitions as the source of truth; do not duplicate them in this issue. Add only the smallest validator needed for the supported subset.

## Dependencies and blockers

- SAS-102: pinned runtime and Guest contract.
- Full Draft 2020-12 support, if required later, should be a separate issue.
- Live Sandbox acceptance remains tracked by SAS-108 and is not evidence for this issue.
